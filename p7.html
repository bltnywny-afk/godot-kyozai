この章は設計メモです

B1〜B6と違い、ここは手順書ではなく方針書です。構成と考え方の要点だけを置いてあります。B6まで作り終えて、実際に取りかかる段になったら、そのとき詳細版を用意してください。先に書いても、そのころには自分の判断で作れるようになっているはずです。

B5・B6はリアルタイムでした。ターン制は根本から設計が違います。毎フレーム動くのではなく、「手番が回ってきたときだけ動く」。ここを混ぜると収拾がつかなくなるので、最初に切り分けてください。

Game

│  ├─ Player
│  └─ Enemy × n
└─ HUD (CanvasLayer)
この章の最重要点

マップの状態をノードで持たないこと。高さも水量も、ただの2次元配列で持ちます。TileMapLayerはその配列を毎ターン描き直す表示装置にすぎません。

こうしておくと、水流の計算が「配列を舐めて隣のマスと比較する」だけの純粋な処理になります。ノードを走査する形にすると、この計算は途端に書けなくなります。設計済みの高低差（0〜2.0、0.25刻み）と水流は、この分離ができているかどうかで難易度が10倍変わります。

1ターンの流れ

入力待ち
  → プレイヤーの行動を確定（データ更新）
  → 全アクターの行動を確定
  → 環境の更新（水が流れる）
  → 表示を更新（Tweenで見せる）
  → アニメ終了を待つ
  → 入力待ちに戻る

データ上は一瞬で確定させ、見た目だけTweenでゆっくり見せます。逆にすると、アニメ中の状態が不定になって必ずバグります。

作る順番

  • 1. 固定マップ・1体・移動だけのターン制
  • 2. 敵を足す（手番が回る順序の確立）
  • 3. 高さの概念を配列に足し、移動可否に反映
  • 4. 水量を足し、毎ターン隣へ流す
  • 5. シャベルと水鉄砲で地形を変えられるようにする
  • 6. 最後にフロアの自動生成
詰まりやすい点

アニメーション中に次の入力を受けてしまい、2手進む。var accepting_input := false のようなフラグでロックします。

自動生成は最後に回してください。先に作ると、デバッグのたびにマップが変わって原因が追えません。

完成の目安

自動生成された1フロアを、地形を掘り水を流して攻略し、階段で次のフロアへ行ける。
