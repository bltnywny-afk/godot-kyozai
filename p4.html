なかまさがし — 幼児向け知育

新しく覚える：データとロジックを分ける／Resourceで問題を持つ／CSV・JSONを外部から読む／UIコンテナで並べる／正解の演出を作る。

この章は設計の練習です

技術的にはB3より易しい部分もあります。それでもここに置いているのは、問題を100問に増やしても、コードを1行も触らずに済む形を作る練習だからです。この形が作れないと、B8の経営シムやB9の農場シムで扱うデータ量に耐えられません。

作るものを先に決める

幼児向けの「なかまさがし」。

画面の上に、同じ仲間のものが2つ並ぶ（たとえば りんご と バナナ）。下に選択肢が2つ（みかん と くるま）。仲間のほうを選ぶ。

正解すると、星が舞って音が鳴り、少し待って次の問題へ。まちがえても止まらない。選んだほうが少し首を振るだけで、もう一度選べる。減点も、やり直しもない。

問題の区切りはなく、延々と続く。問題は毎回シャッフルされる。

まちがいを罰にしない

幼児向けでは、まちがえたときに「ブブー」と大きな音を出したり、画面を赤くしたりすると、そこで遊ぶのをやめます。気づかせるだけで、責めない。選んだものが小さく首を振る程度がちょうどよく、そのまま正解を選べば何事もなく進みます。

この章の考え方の芯

2つ

1. 先に動かして、あとからデータを外に出す。いきなり完璧なデータ構造を設計しようとすると、たいてい1画面も動かないまま終わります。STEP 2〜5では問題をコードに直接書いて動かし、STEP 6で外に出します。この順番が現実的です。

2. 正解がどちらにあるかは、データに書かない。「正解の絵」と「はずれの絵」を持たせておき、左右どちらに置くかは実行時にランダムで決めます。こうすると、いつも右が正解といった偏りが起きません。データを作るときに左右を考えなくて済むのも利点です。

ルートが Control である理由

この章はUIが主役です。第9回のとおり、画面サイズに合わせて伸縮してほしいものは Control 系にします。Node2D で作って座標を打つと、タブレットの画面比が変わった瞬間に崩れます。

選択肢が Button である理由

絵がまだ無いうちは文字を出して進められるからです。Button は text と icon の両方を持てるので、あとで絵ができたら icon に入れるだけで済みます。ノードを差し替える必要がありません。

幼児が指で押すので、Custom Minimum Size は大きめにしてください。間隔（Separation）を広く取るのも、誤タップを防ぐために効きます。

STEP 2

まずは1問、コードに直接書いて出す

データ構造の設計は後回しです。動く形を先に作ります。

# main.gd

extends Control

var current := {}

@onready var choice_a: Button = $Layout/Choices/ChoiceA
@onready var choice_b: Button = $Layout/Choices/ChoiceB


func _ready() -> void:
    current = {
        "samples": ["りんご", "バナナ"],
        "correct": "みかん",
        "wrong": "くるま",
    }
    show_question()


func show_question() -> void:
    # 左右どちらに正解を置くかを、実行時に決める
    var flip := randi() % 2 == 0
    set_choice(choice_a, current["correct"] if flip else current["wrong"], flip)
    set_choice(choice_b, current["wrong"] if flip else current["correct"], not flip)


func set_choice(btn: Button, name: String, is_correct: bool) -> void:
    btn.text = name
    btn.set_meta("correct", is_correct)

set_meta() は、ノードに好きな名前で値をくっつけておける仕組みです。「このボタンが正解かどうか」を持たせるのに使っています。変数を2つ用意して管理するより、ボタン自身に持たせたほうが取り違えません。

ここで確認

F5で、ボタンに「みかん」「くるま」が出る。何度か再起動すると、左右が入れ替わる。

bind の使いどころ

pressed シグナルは「押された」としか教えてくれず、どのボタンかは分かりません。_on_choice.bind(choice_a) と書くと、呼ばれるときに choice_a を引数として渡してくれます。同じ処理を複数のボタンで共有したいときの定番です。

正解のごほうび演出

第8回の AnimationPlayer をここでも使います。演出は Reward にまとめて、そこだけで完結させます。

cheer の中身は、CheerLabel の scale を 0 → 1.2 → 1.0 と動かし、最後に modulate:a を 1 → 0 にするだけで十分です。

Mouse Filter を「無視」にする理由

Reward は画面全面を覆っています。既定のままだと、この見えないパネルがタップを吸い取ってボタンが押せなくなります。演出用に重ねる Control は、必ず Mouse → Filter を「無視」にしてください。ここは非常によく踏む落とし穴です。

STEP 5

まちがえたときの扱い

止めない、責めない。選んだものが小さく首を振るだけにします。

# main.gd の on_wrong を書き換える

func on_wrong(btn: Button) -> void:
    $WrongSound.play()
    var t := create_tween()
    t.tween_property(btn, "rotation", 0.05, 0.06)
    t.tween_property(btn, "rotation", -0.05, 0.12)

回転の中心

Control ノードの回転は既定で左上を軸にします。ChoiceA / ChoiceB の Pivot Offset を、サイズの半分（70, 55）にしてください。設定しないと、ボタンが大きく振り回されます。B1のボタン演出と同じ落とし穴です。

WrongSound は、やさしい音にしてください。ここで強い否定の音を入れると、幼児は次から押すのをためらいます。

ここで確認

違うほうを押すと、そのボタンが小さく左右に揺れる。画面はそのままで、正解を押せば進む。何度まちがえても不利にならない。

STEP 6

データを Resource に移す

ここがこの章の本題です。問題をコードから追い出します。

まず、絵と名前をひとつ持つだけの型を作ります。ファイルシステムで右クリック →「新規スクリプト」で item.gd を作成。

# item.gd

class_name Item
extends Resource

@export var name: String = ""
@export var image: Texture2D

次に、問題ひとつ分をまとめる型です。

# question.gd

class_name Question
extends Resource

@export var group_name: String = ""    # 「くだもの」などのメモ
@export var samples: Array[Item] = []  # お手本（同じ仲間）
@export var correct: Item              # 正解の選択肢
@export var wrong: Item                # はずれの選択肢
Item と Question に分けた理由

「りんご」を、くだものの問題でも、あかい色の問題でも使いたいからです。Item を独立したファイルにしておくと、一度作った絵と名前を、いくつもの問題から使い回せます。りんごの絵を差し替えたら、それを使う全部の問題で変わります。第3回のインスタンス化と同じ発想です。

ファイルの作り方

  • ファイルシステムで右クリック →「新規」→「リソース」
  • 一覧から Item を選ぶ（さっき class_name を付けたので出てきます）
  • res://items/apple.tres のように保存
  • 選択するとインスペクタに Name と Image が出るので、そこに入れる

同じ手順で Question のファイルも作り、samples に Item をドラッグ、correct と wrong にも Item を入れます。

# main.gd に追加（current の型を変える）

@export var questions: Array[Question] = []

var pool: Array[Question] = []
var current: Question = null

@onready var samples_box: HBoxContainer = $Layout/Samples


func next_question() -> void:
    if pool.is_empty():
        pool = questions.duplicate()
        pool.shuffle()
    current = pool.pop_front()
    answered = false
    show_question()


func show_question() -> void:
    for i in samples_box.get_child_count():
        var s: TextureRect = samples_box.get_child(i)
        if i < current.samples.size():
            s.texture = current.samples[i].image
            s.show()
        else:
            s.hide()

    var flip := randi() % 2 == 0
    set_choice(choice_a, current.correct if flip else current.wrong, flip)
    set_choice(choice_b, current.wrong if flip else current.correct, not flip)


func set_choice(btn: Button, item: Item, is_correct: bool) -> void:
    btn.icon = item.image
    btn.text = item.name
    btn.set_meta("correct", is_correct)

_ready の中で問題を組み立てていた部分は削除し、next_question() を呼ぶだけにします。Main を選び、インスペクタの Questions に、作った .tres をドラッグして並べてください。

duplicate() と shuffle()

questions をそのままシャッフルすると、インスペクタで設定した元のデータが並べ替わってしまいます。duplicate() でコピーを作り、そちらを使い切る形にしています。使い切ったらまたコピーし直すので、ひと回りするまで同じ問題は出ません。

ここで確認

インスペクタに並べた問題が、シャッフルされて順に出る。問題を1問足す作業が、Question のファイルを1つ作ってインスペクタに足すだけで済んでいる。コードを触る必要がない。

STEP 6.5

問題を外部ファイルから読む

STEP 6 で問題はコードから出ましたが、まだGodotのエディタを開かないと編集できません。問題を50問に増やすとき、.tres を50個作ってインスペクタに並べるのは骨が折れます。

そこで、問題を表計算ソフトやテキストエディタで編集できるファイルに出します。データの持ち方には3段階あり、ここが3段目です。

持ち方編集する人・道具書き出したあと
コードに直書き自分・Godot変更できない
.tres（Resource）自分・Godot変更できない
CSV / JSON誰でも・表計算やメモ帳置き場所しだいで変更できる

res:// と user:// はまったく別物

ファイルをどこに置くかで、性質が変わります。ここを取り違えると、書き出したあとに「編集できない」と気づいて作り直しになります。

res://user://
実体プロジェクトのフォルダ遊ぶ人のパソコンの保存領域
書き出すと.pck に焼き込まれるそのままファイルとして残る
あとから編集できないできる
書き込みできない（読み取り専用）できる
向いているもの作者が決める問題データセーブデータ、遊ぶ人が足す問題

この章では res:// を使います。問題は作者が決めるものだからです。開発中はプロジェクトのフォルダを直接いじれるので、これで不便はありません。

user:// の実際の場所

フォルダのパスは OS.get_user_data_dir() で調べられます。Windowsなら %APPDATA%\Godot\app_userdata\プロジェクト名、Macなら ~/Library/Application Support/Godot/app_userdata/プロジェクト名 あたりです。実践B6のセーブデータはここに置いています。

CSVで書く

まず問題データです。1行1問の表なので、CSVが向いています。プロジェクトに res://data/ フォルダを作り、2つのファイルを置きます。

# res://data/items.csv

id,name,image
apple,りんご,res://items/apple.png
banana,バナナ,res://items/banana.png
orange,みかん,res://items/orange.png
car,くるま,res://items/car.png
bus,バス,res://items/bus.png
train,でんしゃ,res://items/train.png
# res://data/questions.csv

group,samples,correct,wrong
くだもの,apple|banana,orange,car
のりもの,car|bus,train,apple

絵そのものではなく、絵の場所（パス）を文字列で持ちます。CSVには文字と数字しか書けないためです。読み込むときに load() でその場所から絵を取ってきます。

問題のほうは apple のようなIDで品物を指しています。同じ「りんご」を何問でも使い回せて、りんごの絵を差し替えれば全部の問題で変わります。表を分けてIDで結ぶのは、データを扱うときの定石です。

お手本が2つあるのを | でしのいでいる

CSVは1マスに1つの値しか置けないので、複数のお手本を apple|banana と自分で区切っています。この不格好さがCSVの限界です。次に出てくるJSONなら、配列としてそのまま書けます。

Godotは .csv を翻訳ファイルとして取り込みます

ここは必ず引っかかります。Godot 4 は res:// に置かれた .csv を、翻訳（多言語対応）のファイルだと判断して取り込もうとします。見出しが決まった形になっていないので、インポートエラーが出ます。

直し方は、そのCSVを選び、「インポート」ドックの Import As を「Keep File (exported as is)」に変えて、「再インポート」を押すことです。これで、ただのファイルとして扱われるようになります。

この操作を忘れると、実行時にファイルが見つからないというエラーになります。取り込まれた翻訳データに化けていて、元のCSVが書き出しに含まれないためです。

読み込むコードです。main.gd に足します。

# main.gd に追加

const ITEMS_CSV     := "res://data/items.csv"
const QUESTIONS_CSV := "res://data/questions.csv"


# 品物の表を読む。返すのは { "apple": Item, ... } という辞書
func load_items(path: String) -> Dictionary:
    var items := {}
    if not FileAccess.file_exists(path):
        push_error("ファイルがありません: " + path)
        return items

    var f := FileAccess.open(path, FileAccess.READ)
    f.get_csv_line()                      # 1行目は見出しなので捨てる

    while not f.eof_reached():
        var row := f.get_csv_line()
        if row.size() < 3 or row[0] == "":
            continue                      # 空行や欠けた行は飛ばす
        var it := Item.new()
        it.name  = row[1]
        it.image = load(row[2])
        items[row[0]] = it

    return items
# main.gd に追加

# 問題の表を読む。品物の辞書を渡して、IDから実体を引く
func load_questions(path: String, items: Dictionary) -> Array[Question]:
    var list: Array[Question] = []
    if not FileAccess.file_exists(path):
        push_error("ファイルがありません: " + path)
        return list

    var f := FileAccess.open(path, FileAccess.READ)
    f.get_csv_line()

    while not f.eof_reached():
        var row := f.get_csv_line()
        if row.size() < 4 or row[0] == "":
            continue

        if not items.has(row[2]) or not items.has(row[3]):
            push_warning("知らないIDがあります: " + row[0])
            continue                      # 1問飛ばすだけで、止めない

        var q := Question.new()
        q.group_name = row[0]
        for id in row[1].split("|"):
            if items.has(id):
                q.samples.append(items[id])
        q.correct = items[row[2]]
        q.wrong   = items[row[3]]
        list.append(q)

    return list

あとは _ready で呼ぶだけです。インスペクタの Questions は空のままで構いません。

# _ready を書き換える

func _ready() -> void:
    var items := load_items(ITEMS_CSV)
    questions = load_questions(QUESTIONS_CSV, items)
    if questions.is_empty():
        push_error("問題が1問も読めませんでした")
        return
    next_question()
1行おかしくても、止めない

continue でその行だけ飛ばしているのが要点です。データは手で書くので必ず間違いが混ざります。1行のミスでゲームが起動しなくなると、原因を探すのが苦痛になります。

かわりに push_warning() で「この行が変だった」と出力パネルに残します。遊びは続けられて、あとから直せます。

ここで確認

CSVに1問足して実行すると、その問題が出てくる。Godotのエディタでは何も操作していない。わざとIDを打ち間違えると、その問題だけ飛ばされて、出力パネルに警告が出る。

# main.gd（CSVのかわりに使う場合）

const QUIZ_JSON := "res://data/quiz.json"


func load_quiz(path: String) -> Array[Question]:
    var list: Array[Question] = []
    if not FileAccess.file_exists(path):
        push_error("ファイルがありません: " + path)
        return list

    var f := FileAccess.open(path, FileAccess.READ)
    var data = JSON.parse_string(f.get_as_text())
    if data == null:
        push_error("JSONの形が壊れています: " + path)
        return list

    # 品物
    var items := {}
    var raw_items: Dictionary = data.get("items", {})
    for id in raw_items:
        var d: Dictionary = raw_items[id]
        var it := Item.new()
        it.name  = d.get("name", "")
        it.image = load(d.get("image", ""))
        items[id] = it

    # 問題
    for qd in data.get("questions", []):
        var correct_id: String = qd.get("correct", "")
        var wrong_id: String   = qd.get("wrong", "")
        if not items.has(correct_id) or not items.has(wrong_id):
            push_warning("知らないIDがあります")
            continue
        var q := Question.new()
        q.group_name = qd.get("group", "")
        for id in qd.get("samples", []):
            if items.has(id):
                q.samples.append(items[id])
        q.correct = items[correct_id]
        q.wrong   = items[wrong_id]
        list.append(q)

    return list
JSONの数字は全部 float になります

JSONには整数と小数の区別がないため、Godotは数値を全部 float として読みます。3 と書いても 3.0 で返ります。

配列の添字や % の計算に使うとエラーになるので、int(data["回数"]) のように包んで整数へ戻します。実践B6のセーブデータ読み込みでも同じことをしています。

この章の問題データは文字列だけなので、今回は関係ありません。数値のパラメータ（敵の攻撃力、制限時間など）を持たせるときに効いてきます。

キーが無いときに落ちないように

data["items"] と直接書くと、キーが無いときにエラーで止まります。data.get("items", {}) と書けば、無いときは空の辞書が返るだけで済みます。第2引数が「無かったときの値」です。

どちらを使うか

CSVJSON
形表（1行1件）入れ子にできる
作る道具表計算ソフトで作れるテキストエディタ
配列を持つ苦手（区切り文字でしのぐ）得意
項目数が可変苦手得意
向いているもの敵の能力表、アイテム表、問題集設定ファイル、階層のあるデータ

項目が決まっていて件数が多いならCSV、形が入り組んでいるならJSON。この章の問題データはどちらでも書けるので、表計算で量産したいならCSV、お手本の数を問題ごとに変えたいならJSONです。

Excelから出すときは文字コードに注意

Excelで「CSVとして保存」すると、環境によってはShift_JISで書き出されます。GodotはUTF-8しか読めないので、日本語が化けます。

「CSV UTF-8（コンマ区切り）」という形式を選ぶか、Googleスプレッドシートを使ってください（こちらは既定でUTF-8です）。文字化けしたら、まずここを疑います。

STEP 7

問題を増やして、仕上げる

ここからは絵とデータを作る作業です。コードはもう触りません。問題を足すのはCSVに1行足すだけなので、表計算ソフトを開いて量産できます。

  • まず10問。くだもの／のりもの／どうぶつ／たべもの あたりで作ると、幼児にも仲間の区別がつきます。
  • はずれは「明らかに違うもの」から始める。りんご・バナナ に対して くるま。ここで「みかん と ぶどう のどちらが正解か」のような難問を入れると、幼児は選べません。
  • お手本は2つで十分。1つだと仲間の共通点が伝わらず、3つだと画面が混みます。
  • 文字は残しておく。絵を入れても text を消さないでおくと、大人が横で読んであげられます。
  • ごほうびに変化を。正解時の言葉を「せいかい！」「すごい！」「よくできました！」からランダムに選ぶと、飽きが来にくくなります。
完成の目安

10問がシャッフルされて延々と出る。正解すると星が舞って次へ進む。まちがえても止まらず、何度でも選べる。問題を1問足すのに、CSVを1行足すだけで済み、Godotを開く必要すらない。ここまでできたら完成です。

余裕ができたら足す機能

ここから先は作らなくても完成です。上から順に、だいたい簡単な順です。「プロンプトをコピー」を押すと、このゲームの内容とコードの作りまで入った質問文がコピーされます。

やさしい

ほめ言葉をランダムにする

「せいかい！」だけでなく、数種類からランダムに選ぶ。飽きにくくなります。

やさしい

音声で問題を読み上げる

「なかまは どっち？」や選択肢の名前を、録音した声で再生する。文字が読めない子には効果が大きいです。

やさしい

お手本を3つにする

共通点がより伝わりやすくなります。いまのコードは既に3つに対応できる形なので、ノードを増やすだけで済むはずです。

ふつう

選択肢を3つ・4つに増やす

慣れてきた子には難しくできる。ボタンを動的に作る形になるので、UIの作り方が一段深くなります。

ふつう

カテゴリを選べるようにする

「くだもの」「のりもの」など、遊ぶ分野を最初に選ぶ。問題データにグループ名を持たせてあるので、絞り込むだけで作れます。

ふつう

まちがえたらそっとヒント

2回まちがえたら、正解のほうがほんのり光る。詰まって離脱するのを防げます。

むずかしい

苦手な仲間を覚えておく

まちがえたグループを記録し、そのグループの問題を多めに出す。地味ですが、知育としての効果が一番大きい改良です。

ふつう

書き出したあとでも問題を足せるようにする

いまは res:// なので、書き出すと問題を変えられません。初回起動時に user:// へコピーし、以降はそちらを読むようにすると、配ったあとでも問題を足せるようになります。

むずかしい

問題を画面から追加できるようにする

エディタを開かなくても、アプリの中で写真を撮って問題を作れる。手間はかかりますが、自分の家のものを問題にできます。

むずかしい

ドラッグして仲間の輪に入れる

選ぶのではなく、正しいほうを丸の中へ引っ張り込む。操作が直感的になり、幼児にはこちらのほうが分かりやすい場合があります。

# main.gd

extends Control

const ITEMS_CSV     := "res://data/items.csv"
const QUESTIONS_CSV := "res://data/questions.csv"

@export var questions: Array[Question] = []

var pool: Array[Question] = []
var current: Question = null
var answered := false

@onready var samples_box: HBoxContainer = $Layout/Samples
@onready var choice_a: Button = $Layout/Choices/ChoiceA
@onready var choice_b: Button = $Layout/Choices/ChoiceB
@onready var reward_anim: AnimationPlayer = $Reward/AnimationPlayer


func _ready() -> void:
    choice_a.pressed.connect(_on_choice.bind(choice_a))
    choice_b.pressed.connect(_on_choice.bind(choice_b))

    var items := load_items(ITEMS_CSV)
    questions = load_questions(QUESTIONS_CSV, items)
    if questions.is_empty():
        push_error("問題が1問も読めませんでした")
        return

    next_question()


# ---- 外部データの読み込み ----
func load_items(path: String) -> Dictionary:
    var items := {}
    if not FileAccess.file_exists(path):
        push_error("ファイルがありません: " + path)
        return items

    var f := FileAccess.open(path, FileAccess.READ)
    f.get_csv_line()                      # 見出しを捨てる

    while not f.eof_reached():
        var row := f.get_csv_line()
        if row.size() < 3 or row[0] == "":
            continue
        var it := Item.new()
        it.name  = row[1]
        it.image = load(row[2])
        items[row[0]] = it

    return items


func load_questions(path: String, items: Dictionary) -> Array[Question]:
    var list: Array[Question] = []
    if not FileAccess.file_exists(path):
        push_error("ファイルがありません: " + path)
        return list

    var f := FileAccess.open(path, FileAccess.READ)
    f.get_csv_line()

    while not f.eof_reached():
        var row := f.get_csv_line()
        if row.size() < 4 or row[0] == "":
            continue

        if not items.has(row[2]) or not items.has(row[3]):
            push_warning("知らないIDがあります: " + row[0])
            continue

        var q := Question.new()
        q.group_name = row[0]
        for id in row[1].split("|"):
            if items.has(id):
                q.samples.append(items[id])
        q.correct = items[row[2]]
        q.wrong   = items[row[3]]
        list.append(q)

    return list


# ---- 出題 ----
func next_question() -> void:
    if pool.is_empty():
        pool = questions.duplicate()
        pool.shuffle()
    current = pool.pop_front()
    answered = false
    show_question()


func show_question() -> void:
    for i in samples_box.get_child_count():
        var s: TextureRect = samples_box.get_child(i)
        if i < current.samples.size():
            s.texture = current.samples[i].image
            s.show()
        else:
            s.hide()

    # 正解を左右どちらに置くかは、実行時に決める
    var flip := randi() % 2 == 0
    set_choice(choice_a, current.correct if flip else current.wrong, flip)
    set_choice(choice_b, current.wrong if flip else current.correct, not flip)


func set_choice(btn: Button, item: Item, is_correct: bool) -> void:
    btn.icon = item.image
    btn.text = item.name
    btn.rotation = 0.0
    btn.set_meta("correct", is_correct)


# ---- 判定 ----
func _on_choice(btn: Button) -> void:
    if answered:
        return
    if btn.get_meta("correct"):
        answered = true
        on_correct(btn)
    else:
        on_wrong(btn)


func on_correct(_btn: Button) -> void:
    $CorrectSound.play()
    $Reward/Stars.restart()
    reward_anim.play("cheer")
    await reward_anim.animation_finished
    await get_tree().create_timer(0.3).timeout
    next_question()


func on_wrong(btn: Button) -> void:
    $WrongSound.play()
    var t := create_tween()
    t.tween_property(btn, "rotation", 0.05, 0.06)
    t.tween_property(btn, "rotation", -0.05, 0.12)
    t.tween_property(btn, "rotation", 0.0, 0.06)
