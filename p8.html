経営シミュレーション

新しく覚える：時間進行の管理／大量データをResourceで持つ／表主体のUI／数値バランスの詰め方。

この章は設計メモです

B1〜B6と違い、ここは手順書ではなく方針書です。構成と考え方の要点だけを置いてあります。B6まで作り終えて、実際に取りかかる段になったら、そのとき詳細版を用意してください。先に書いても、そのころには自分の判断で作れるようになっているはずです。

アクション性はありませんが、別の難しさがあります。要素が増えるほど互いに影響し合うため、設計が甘いと途中で手が入れられなくなります。B4でやったデータとロジックの分離が、ここで本番を迎えます。

構成 — ロジックはUIを知らない

Main
├─ SimClock (Node)       ← 1日／1週を進める
├─ Economy (Node)        ← 収支の計算。画面のことを一切知らない
└─ UI (CanvasLayer)
   ├─ TabContainer
   │  ├─ 概要 / 商品 / 従業員 / 施設
   └─ DayEndPanel

Autoload: SaveManager

Economy は計算して day_ended(report) のようなシグナルを出すだけ。UIはそれを受けて表示を更新します。この向き（第13回）を守ると、UIを全部作り直しても計算部分は無傷で残ります。

商品や施設はResourceで

class_name ItemData extends Resource

@export var name: String
@export var cost: int
@export var price: int
@export var popularity: float

これで商品1つが1ファイルになります。増やすのも、バランス調整も、エディタ上でできます。コードに数値を直接書くと、調整のたびに再起動することになります。

作る順番

  • 1. ボタンを押すと1日進み、収支が表示されるだけのもの
  • 2. 商品を1種類。仕入れて売る
  • 3. 商品を複数に。ItemDataをResource化
  • 4. 従業員か施設のどちらか一方だけ足す
  • 5. セーブとロード
  • 6. 最後に数値バランス
詰まりやすい点

バランスは机上では決まりません。先に作って、遊んでから決めるものです。最初から緻密な経済モデルを設計しようとすると、たいてい1画面も動かないまま終わります。

完成の目安

10日間プレイして、やり方次第で黒字にも赤字にもなる。判断に意味が生まれたら完成です。
